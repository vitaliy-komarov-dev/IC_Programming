## Вариант 1. Через временную таблицу и подзапрос

### Краткое название

**«Продажи поставщикам» (через временную таблицу)** — поиск номенклатуры, которую продавали контрагентам, одновременно являющимся поставщиками организации.

### Описание

Запрос находит товары, по которым есть **и закупка (поступление), и продажа (реализация)** одному и тому же контрагенту. То есть контрагент выступает одновременно в роли поставщика и покупателя.

### Код запроса

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ПоступлениеТоваров.Контрагент
ПОМЕСТИТЬ Поставщики
ИЗ
    Документ.ПоступлениеТоваров КАК ПоступлениеТоваров
;

////////////////////////////////////////////////////////////////////////////////
ВЫБРАТЬ РАЗЛИЧНЫЕ
    РеализацияТоваровТовары.Номенклатура,
    РеализацияТоваровТовары.Ссылка.Контрагент
ИЗ
    Документ.РеализацияТоваров.Товары КАК РеализацияТоваровТовары
ГДЕ
    РеализацияТоваровТовары.Ссылка.Контрагент В
            (ВЫБРАТЬ
                Поставщики.Контрагент
            ИЗ
                Поставщики КАК Поставщики)
```

### Как это работает

#### Шаг 1. Список поставщиков

Выбираются уникальные контрагенты из документов **«ПоступлениеТоваров»** и помещаются во временную таблицу `Поставщики`.

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ПоступлениеТоваров.Контрагент
ПОМЕСТИТЬ Поставщики
ИЗ
    Документ.ПоступлениеТоваров КАК ПоступлениеТоваров
```

#### Шаг 2. Основная выборка

Из табличной части **«Товары»** документов **«РеализацияТоваров»** выбираются уникальные пары «Номенклатура — Контрагент», но только по тем контрагентам, которые есть во временной таблице `Поставщики`.

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    РеализацияТоваровТовары.Номенклатура,
    РеализацияТоваровТовары.Ссылка.Контрагент
ИЗ
    Документ.РеализацияТоваров.Товары КАК РеализацияТоваровТовары
ГДЕ
    РеализацияТоваровТовары.Ссылка.Контрагент В
            (ВЫБРАТЬ
                Поставщики.Контрагент
            ИЗ
                Поставщики КАК Поставщики)
```

### Схема работы

| Этап | Действие | Источник | Результат |
|:----:|----------|----------|-----------|
| 1 | Выбор уникальных контрагентов | `Документ.ПоступлениеТоваров` | Временная таблица `Поставщики` |
| 2 | Выбор пар «Номенклатура — Контрагент» | `Документ.РеализацияТоваров.Товары` | Уникальные пары |
| 3 | Фильтрация по подзапросу | Условие `В (...)` | Только контрагенты-поставщики |

### Ключевые конструкции

| Конструкция | Назначение |
|-------------|-----------|
| `РАЗЛИЧНЫЕ` | Убирает дублирование строк |
| `ПОМЕСТИТЬ` | Создаёт временную таблицу |
| `В (...)` | Подзапрос для фильтрации |
| `Ссылка.Контрагент` | Обращение к реквизиту шапки документа через табличную часть |

## Вариант 2. Через внутреннее соединение (INNER JOIN)

### Краткое название

**«Продажи поставщикам» (через INNER JOIN)** — поиск номенклатуры, которую продавали контрагентам, одновременно являющимся поставщиками организации.

### Описание

Альтернативный вариант того же запроса, что и в Варианте 1, но вместо `ПОМЕСТИТЬ` + подзапроса `В (...)` используется **внутреннее соединение (INNER JOIN)** двух источников по контрагенту.

### Код запроса

```sql
ВЫБРАТЬ РАЗЛИЧНЫЕ
    ПоступлениеТоваров.Контрагент,
    РеализацияТоваровТовары.Номенклатура
ИЗ
    Документ.ПоступлениеТоваров КАК ПоступлениеТоваров
        ВНУТРЕННЕЕ СОЕДИНЕНИЕ Документ.РеализацияТоваров.Товары КАК РеализацияТоваровТовары
        ПО ПоступлениеТоваров.Контрагент = РеализацияТоваровТовары.Ссылка.Контрагент
```

### Как это работает

Запрос соединяет два источника данных:

| Источник | Что берём |
|----------|-----------|
| `Документ.ПоступлениеТоваров` | Контрагент (поставщик) |
| `Документ.РеализацияТоваров.Товары` | Номенклатура и контрагент (покупатель) |

**Условие соединения:** `ПоступлениеТоваров.Контрагент = РеализацияТоваровТовары.Ссылка.Контрагент`

То есть строки остаются только там, где **контрагент из поступления совпадает с контрагентом из реализации**. Это и есть контрагент, который одновременно поставщик и покупатель.

Ключевое слово `РАЗЛИЧНЫЕ` убирает дубли, которые появляются из-за множества документов поступлений и реализаций по одному контрагенту.

### Схема работы

```
┌─────────────────────────┐         ┌──────────────────────────────┐
│ Документ.ПоступлениеТо- │         │ Документ.РеализацияТоваров.  │
│ варов                   │         │ Товары                       │
│  • Контрагент           │◄───────►│  • Ссылка.Контрагент         │
└─────────────────────────┘  JOIN   │  • Номенклатура              │
                                    └──────────────────────────────┘
                    │
                    ▼
        Пары «Контрагент — Номенклатура»
        (контрагент = и поставщик, и покупатель)
```

### Ключевые конструкции

| Конструкция | Назначение |
|-------------|-----------|
| `РАЗЛИЧНЫЕ` | Убирает дубли строк |
| `ВНУТРЕННЕЕ СОЕДИНЕНИЕ` | Оставляет только совпадающие записи из двух источников |
| `ПО ... = ...` | Условие соединения по контрагенту |
| `Ссылка.Контрагент` | Обращение к реквизиту шапки документа через табличную часть |

## Сравнение двух вариантов

| Вариант | Подход | Особенности |
|---------|--------|-------------|
| **Вариант 1** | `ПОМЕСТИТЬ` + `В (...)` | Временная таблица, явный список поставщиков, удобно читать по шагам |
| **Вариант 2** | `ВНУТРЕННЕЕ СОЕДИНЕНИЕ` | Один запрос, обычно эффективнее по производительности, короче |

Оба запроса дают **эквивалентный результат**, но по-разному его получают.

## Применение

- Анализ взаиморасчётов с контрагентами-партнёрами.
- Поиск товаров с полным циклом «закупка → продажа».
- Подготовка отчётов по совместному обороту.
- Проверка полноты данных по контрагентам.

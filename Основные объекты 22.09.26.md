## 🚀 Шпаргалка (1–2 страницы)

### 🧱 Табличные части на форме списка

| Что делаем | Как |
|---|---|
| Добавить ТЧ в форму списка | Открыть форму списка → развернуть «Динамический список» → перетащить ТЧ (Товары / Услуги) на форму |
| Две ТЧ рядом (в 2 колонки) | Добавить **обычную группу** (не «Страницы»!) → свойство **«Группировка» = Горизонтальная всегда** → закинуть обе ТЧ в группу |
| Убрать лишние командные панели | У каждой ТЧ на форме → снять свойство **«Автозаполнение командной панели»** |
| Скрыть лишний столбец (Ссылка) | У столбца → снять свойство **«Видимость»** |

> 💡 Группа «Страницы» = вкладки. Обычная группа = просто контейнер. Для двух таблиц рядом — **обычная** + горизонтальная группировка.

### 📒 Журнал документов

| Понятие | Значение |
|---|---|
| **Назначение** | Один список для документов **разных видов** (как одна таблица) |
| **Где создать** | `Документы → Журналы документов → Insert` |
| **Подсистема** | Обычно «Общие» / «Журналы» |
| **Стандартные реквизиты** | **Ссылка**, **Дата**, **Номер**, **Проведён**, **ПометкаУдаления**, **Тип** |
| **Тип** | Составной: тип конкретного документа (получается через `Тип()` / `ТипЗнч()`) |
| **Регистрируемые документы** | Вкладка «Данные» → галочки у нужных документов (у нас: Поступление, Реализация (старая), Продажа (новая)) |
| **Команды** | Только одна — **открыть список**. Создание — на форме журнала (по видам документов) |
| **Графы** | Столбцы журнала. Указываем: имя + **какой реквизит документа** поставляет данные |
| **Нет данных** | В ячейке будет **NULL** (не 0, не пустая строка) — «невозможно получить данные» |

> 💡 Журнал физически дублирует данные документов. При создании документа запись появляется **и в таблице документа, и в таблице журнала**.

### 🗃️ Регистры сведений (базово)

| Понятие | Значение |
|---|---|
| **Зачем** | Хранить **состояние** (периодические данные, историю), а не справочные данные |
| **Три типа полей** | **Ресурсы** (что храним), **Измерения** (в разрезе чего ищем), **Реквизиты** (характеристика записи) |
| **Периодичность** | Позволяет хранить историю. Даёт **Срез последних / Срез первых** |
| **Режим записи** | **Независимый** / **Подчинение регистратору** |
| **Подчинение регистратору** | Записи делает документ. Появляются поля: **Период**, **Регистратор**, **НомерСтроки**, **Активность** |
| **Периодичность по регистратору** | Запись можно сделать только **одним** документом в рамках его позиции |
| **Ведущее измерение** | Индексируется + при удалении объекта записи регистра **обнуляются** + в форме объекта появляется команда перехода к записям |
| **Запрет незаполненных** | Не даёт записать запись с пустым измерением |

> ⚠️ Ключ регистра сведений = **набор измерений** (+ период, если периодический; + регистратор, если подчинён и периодичность ≥ регистратор). **Номер строки в ключ НЕ входит** → одинаковые наборы измерений в одном документе записать нельзя.

### 🔁 Конструктор движений

| Шаг | Действие |
|---|---|
| Запуск | ПКМ по документу → **Конструкторы → Конструктор движений** (или вкладка «Движения») |
| Настройка | Слева — данные регистра, справа — данные документа. Настраиваем соответствие полей |
| «Заполнить выражение» | Автозаполнение по совпадению **имени** и **типа** (в т.ч. по базовому типу!) |
| ТЧ | Если данные в ТЧ — выбрать табличную часть (Товары) |
| Результат | Процедура **ОбработкаПроведения** в модуле объекта: `Движения.ЦеныПоставщиков.Записывать = Истина;` + цикл по ТЧ + `Добавить()` + заполнение полей |

> 💡 `Движения.ЦеныПоставщиков` — это **набор записей** (аналог таблицы в оперативной памяти). `Записывать = Истина` → при фиксации транзакции данные уедут в БД.

### 🔗 Типы соединений в запросах

| Тип | Что берём | NULL возможен? |
|---|---|---|
| **Внутреннее** | Только совпавшие строки | ❌ никогда |
| **Левое** | Все строки **левой** таблицы + совпадения из правой | ✅ в правой части |
| **Правое** | Все строки **правой** таблицы + совпадения из левой | ✅ в левой части |
| **Полное** | Все строки **обеих** таблиц | ✅ с обеих сторон |

> 💡 «Каждый с каждым» (без условия связи) = **декартово произведение**, количество строк = произведение количеств.

## 📚 Полный конспект

### 1. Введение: с чего начали занятие

- Преподаватель запускает процесс, всплывает ошибка блокировки: где-то уже висит открытый конфигуратор. **Вывод:** повторный запуск конфигуратора при уже открытом сеансе даёт ошибку блокировки.
- Вспомнили, на чём остановились: **печать документа** и работа с **модулем менеджера**.
- Ключевая мысль прошлого занятия: методы печати лежат в **модуле менеджера**, потому что:
  - метод относится к объекту метаданных (продажи/товары), но **не требует объектного типа**;
  - работаем не с объектом «Документ», достаточно знать **ссылки**;
  - все данные берём **запросом из базы**, причём сразу со множеством объектов.
- Особенность того запроса: выбиралась **ячейка, которая сама является таблицей**. Запросом внутрь такой ячейки залезть нельзя — это разбирается **программно**: из ячейки делается новая выборка, из неё — ещё одна.

> 🎯 Переход к теме: у нас есть список документов, и в нём не хватает табличных частей. Плюс нужен единый список разнотипных документов.

### 2. Табличные части на форме списка документов

#### Задача

В форме списка «Продажи товаров» показывается только основная таблица документов. Нужно добавить под список **табличные части** — «Товары» и «Услуги» — из документа, на котором стоит курсор.

#### Как добавить ТЧ

1. Открыть **форму списка** документа.
2. Развернуть справа **«Динамический список»** (объект формы).
3. Взять табличную часть (**Товары**) и **перетащить на форму** (вниз).
4. Согласиться с добавлением таблицы и колонок.
5. Повторить для **Услуг**.

Результат: под списком документов появляются две таблицы, связанные с текущим документом.

#### Как поставить две ТЧ рядом (в две колонки)

Проблема: одна под другой — неудобно и неинформативно.

Решение:
1. Встать на «Товары» → добавить **обычную группу** (не «Страницы»!).
2. Свойство группы **«Группировка» = Горизонтальная всегда**.
3. Закинуть в группу **обе** табличные части.
4. Заголовок группы можно не показывать (свойство «Отображать заголовок»).

> 💡 «Страницы» = вкладки. Нам нужен **обычный контейнер** без визуального разделения.

#### Косметика

- У каждой ТЧ на форме: снять **«Автозаполнение командной панели»** — нам нужны таблицы только для просмотра.
- Скрыть лишний столбец **«Ссылка»**: у столбца снять свойство **«Видимость»**.

> ⚠️ Важно: если ТЧ нужны только для просмотра — командную панель отключаем, иначе пользователь сможет их редактировать «в обход» документа.

### 3. Журнал документов

#### Зачем нужен

Иногда нужно работать со списком **разнотипных документов** как с одной таблицей. Такой список можно собрать и вручную (динамический список + объединение двух таблиц), но это будет **визуальный кусочек**, живущий только в памяти, — не объект. Для этого в 1С есть отдельный объект — **Журнал документов**.

#### Что это физически

- Таблица журнала **физически существует в базе**.
- Данные в неё **дублируются** из основных таблиц документов, входящих в журнал.
- При создании нового документа запись создаётся **и в таблице документа, и в журнале**.

#### Создание

1. `Документы → Журналы документов → Insert`.
2. Задать **имя** (например, `СкладскиеДокументы`), **синоним**.
3. Указать **подсистему** (у нас — «Общие» / «Журналы»).
4. Вкладка **«Данные»** → отметить галочками **регистрируемые документы**:
   - Поступление товаров;
   - Реализация (старая);
   - Продажа товаров (новая).
5. Вкладка **«Графы»** → добавить нужные столбцы (см. раздел 4).
6. Сохранить (`Ctrl+S`), применить (`F7`), запустить (`F5`).

#### Команды

- У журнала **всего одна команда** — «Открыть список документов, входящих в журнал».
- Она попадает в **панель навигации** подсистемы.
- **Команды создания** на форме журнала появляются **по видам документов** (по одной на каждый вид). Создаётся документ соответствующего вида, запись журнала дублируется.

> 💡 В подсистеме журнал — это **группирующая сущность**. Визуализации по нему нет, кроме команды открытия списка.

#### Стандартные реквизиты журнала

| Реквизит | Что хранит |
|---|---|
| **Ссылка** | Ссылка на документ (уникальна в рамках всей БД: номер таблицы + УИД) |
| **Дата** | Дата документа |
| **Номер** | Номер документа |
| **Проведён** | Признак проведения |
| **ПометкаУдаления** | Признак пометки на удаление |
| **Тип** | **Тип** конкретного документа (составной тип, получается через `Тип()` / `ТипЗнч()`) |

> 💡 Поле «Тип» — это **примитивный тип** (описание типа), а не ссылка. В запросе — `ТИПЗНАЧЕНИЯ()`, в коде — `ТипЗнч()`.

### 4. Функциональные опции и графы журнала

#### Как добавить графу

1. Вкладка **«Графы»** → `Insert`.
2. Задать **имя** графы (например, `Склад`, `Контрагент`, `СуммаДокумента`).
3. Указать, **какой реквизит документа** поставляет данные в эту графу (для каждого из регистрируемых документов).
4. Подтвердить кнопкой **ОК** (не закрывать крестом!).

#### Примеры граф

| Графа | Откуда берём |
|---|---|
| **Склад** | У всех трёх документов — реквизит `Склад` |
| **Контрагент** | Из Поступления и старой Реализации — `Контрагент`; из новой Продажи — `КонтактноеЛицо` (никто не запрещает разные типы!) |
| **СуммаДокумента** | У новых документов — реквизит `СуммаДокумента`; у старой Реализации — **нет данных → NULL** |

> ⚠️ Тип данных графы **не обязан** совпадать с типом источника. Он **составной** — может быть разным у разных документов.

#### Про NULL

- Если для какого-то документа **неоткуда взять данные** — в ячейке будет **NULL** (не 0, не пустая строка).
- «Система за нас ничего не додумает»: раз нет правила — ставит NULL.
- Это **не «неопределено»** — это именно «значение не может быть получено».

#### Взаимодействие с функциональными опциями

- У нас есть функциональная опция **«Учет по складам»** (включена).
- Если тип данных графы **один** (только `Склад`) — функциональная опция **автоматически скрывает** графу, когда опция выключена.
- Если тип данных **составной** (например, `Склад` + `Сотрудник`) — автоматика **ломается**, и видимостью графы должен управлять **программист** вручную.
- **Форма сама не пересобирается** при изменении функциональной опции — нужно **закрыть и открыть заново** (или использовать `Перечитать()` для данных, но не для структуры).

> 💡 «Обновить» (`F5`) — перечитывает **данные** на форме, но **не пересобирает** структуру формы. Для пересборки — закрыть/открыть.

### 5. Регистры сведений: зачем нужны

#### Проблема

Нам нужно хранить **цену поступления товара от каждого конкретного поставщика**, чтобы при следующем вводе документа брать ту же цену.

Варианты хранения:

| Вариант | Проблема |
|---|---|
| Реквизит справочника «Номенклатура» | Одна цена на всех — не привязать к контрагенту |
| Табличная часть справочника | Нет даты/истории: каждый новый документ перезаписывает цену, старые теряются |
| Табличная часть + дата + регистратор | «Велосипед» — уже есть готовый объект |

#### Решение — регистр сведений

- Регистр сведений хранит **состояние** (периодические данные, историю).
- Три типа полей:
  - **Ресурсы** — что храним (например, `Цена`);
  - **Измерения** — в разрезе чего ищем (например, `Контрагент`, `Номенклатура`);
  - **Реквизиты** — характеристика записи (доп. данные).
- **Периодичность** — позволяет хранить историю. Даёт готовый функционал **Срез последних / Срез первых**.
- **Режим записи**:
  - **Независимый** — записи делаются вручную/кодом;
  - **Подчинение регистратору** — записи делает документ.

#### Подчинение регистратору

При включении появляются поля:

| Поле | Что значит |
|---|---|
| **Период** | Момент времени, с которого действует запись |
| **Регистратор** | Документ, сделавший запись |
| **НомерСтроки** | Номер записи (не номер строки документа!) |
| **Активность** | Участвует ли запись в расчётах (по умолчанию `Истина`) |

- **Периодичность по регистратору** — запись можно сделать только **одним** документом в рамках его позиции. Первый документ сделал запись — второй по той же позиции уже не сможет.
- **Активность**: запись активна → участвует в расчётах; неактивна → в регистре есть, но ни на что не влияет.

### 6. Регистр сведений «Цены поставщиков»

#### Создание

1. `Регистры сведений → Insert`.
2. **Имя:** `ЦеныПоставщиков`.
3. **Режим записи:** **Подчинение регистратору**.
4. **Периодичность:** **По регистратору**.
5. Вкладка **«Регистраторы»** — отметить документ **«Поступление товаров»**.
6. Вкладка **«Данные»**:
   - **Ресурс** `Цена` (тип: `Денежный`, определяемый);
   - **Измерение** `Контрагент` (тип: `СправочникСсылка.Контрагенты`, **Ведущее**, **Запрет незаполненных**);
   - **Измерение** `Номенклатура` (тип: `СправочникСсылка.Номенклатура`, **Ведущее**, **Запрет незаполненных**).
7. Подсистема — «Общие» / «Журналы».
8. Сохранить, применить, запустить.

#### Порядок измерений

- **Важен**: влияет на порядок столбцов и на порядок **индексации**.
- Если оба измерения ведущие — индексация собирается в указанном порядке.
- Неправильный порядок может **замедлить** поиск при связях.

#### Ведущее измерение — три следствия

1. **Индексируется** по умолчанию (свойство «Индексировать» становится серым).
2. При **удалении объекта** (контрагента/номенклатуры) все записи регистра по нему **обнуляются**.
3. В **форме объекта** появляется **команда перехода** к записям регистра с отбором по этому объекту.

#### Команды регистра

- У подчинённого регистра **только одна команда** — открыть список, и та **невидима**.
- Причина: записи делает только документ-регистратор, пользователю напрямую в регистр лезть нечего.
- Администратор может посмотреть через **«Все функции»**.

> ⚠️ Если регистр не включён ни в одну подсистему — при сохранении будет **критическая ошибка** (три восклицательных знака), и `F7` не применится. Нужно добавить в подсистему.

### 7. Конструктор движений: документ → регистр

#### Запуск

- ПКМ по документу → **Конструкторы → Конструктор движений**;
- или вкладка **«Движения»** в документе → кнопка **«Конструктор движений»**.

> ⚠️ Если движения **уже есть** и запустить конструктор заново — при завершении конфигуратор может **упасть** (крэш). Это известная проблема, лучше делать вручную.

#### Настройка

1. Слева — **данные регистра**, справа — **данные документа**.
2. Настроить соответствие полей:
   - `Контрагент` ← `Контрагент` (из шапки);
   - `Номенклатура` ← `Номенклатура` (из ТЧ «Товары»);
   - `Цена` ← `Цена` (из ТЧ «Товары»).
3. Выбрать **табличную часть** «Товары» (иначе полей ТЧ не будет в списке).
4. Кнопка **«Заполнить выражение»** — автозаполнение по совпадению **имени** и **типа** (в т.ч. по **базовому** типу: число подходит к числу, даже если тип определяемый).

#### Что генерируется

Процедура **`ОбработкаПроведения`** в **модуле объекта** документа:

```bsl
Процедура ОбработкаПроведения(Отказ, Режим)
    Движения.ЦеныПоставщиков.Записывать = Истина;
    Для Каждого ТекСтрокаТовары Из Товары Цикл
        Движение = Движения.ЦеныПоставщиков.Добавить();
        Движение.Период = Дата;
        Движение.Контрагент = Контрагент;
        Движение.Номенклатура = ТекСтрокаТовары.Номенклатура;
        Движение.Цена = ТекСтрокаТовары.Цена;
    КонецЦикла;
КонецПроцедуры
```

#### Разбор

| Элемент | Что делает |
|---|---|
| `Движения.ЦеныПоставщиков` | **Набор записей** регистра (аналог таблицы в оперативной памяти) |
| `.Записывать = Истина` | При фиксации транзакции данные уедут в БД |
| `.Добавить()` | Добавляет новую строку в набор |
| `Движение.Период = Дата` | Период = дата документа (технически можно любую — «отложенная запись») |
| `Движение.Регистратор` | Платформа заполнит **автоматически** ссылкой на документ |
| `Движение.НомерСтроки` | Платформа заполнит **автоматически** |

> 💡 `Движения` — коллекция **всех** регистров, для которых документ является регистратором. Для каждого — свой набор записей.

#### Ключ регистра сведений

- Ключ = **набор измерений** (+ период, если периодический; + регистратор, если подчинён и периодичность ≥ регистратор).
- **Номер строки в ключ НЕ входит**.
- Следствие: **несколько одинаковых позиций** (один контрагент + одна номенклатура) в одном документе записать **нельзя** — будет ошибка.

### 8. Теория: типы соединений в запросах

#### Зачем

Когда данные лежат в **двух (или трёх) таблицах**, их нужно соединять. Тип соединения определяет, какие строки попадут в результат.

#### Пример

- Таблица 1: `Номенклатура` + `Номер1` (Ручка→1, Карандаш→2, Вилка→3, Килограммы→4).
- Таблица 2: `Единица` + `Номер2` (Штуки→1, Граммы→3, Банки→1).

#### Четыре типа

| Тип | Что берём | Пример результата |
|---|---|---|
| **Внутреннее** | Только совпавшие | Ручка (2 раза: Штуки, Банки), Вилка (Граммы) |
| **Левое** | Все строки **левой** + совпадения | + Карандаш (NULL), Килограммы (NULL) |
| **Правое** | Все строки **правой** + совпадения | + Килограммы (NULL слева) |
| **Полное** | Все строки **обеих** | Всё вместе |

#### «Каждый с каждым»

- Без условия связи — **декартово произведение**.
- Количество строк = произведение количеств (4 × 3 = 12).

#### NULL

- **Внутреннее** — NULL **не бывает** по определению.
- **Левое** — NULL в **правой** части.
- **Правое** — NULL в **левой** части.
- **Полное** — NULL с **обеих** сторон.

> 💡 На практике чаще всего **внутреннее** и **левое**. Конструктор запросов не любит правое — переворачивает в левое, теряя стандартность связей (пишет «произвольные условия»).

### 9. Хранилище конфигурации (задел на будущее)

- Нужно, когда **несколько программистов** работают с одной конфигурацией.
- Все базы подключаются к **одному хранилищу** → структура едина для всех.
- Редактировать объект может **только один** — нужно **захватить** объект.
- Чтобы добавить новый объект — захватить **корень конфигурации**, добавить, отпустить.
- В **учебной** версии хранилища **нет** — только в боевой/девелоперской.

> ⚠️ Важно при работе с регистром: он **взаимодействует с двумя объектами** (регистр + документ-регистратор). Галочка «регистратор» взаимосвязана: поставил в регистре — появилась в документе, снял в документе — слетела в регистре. При обновлении из хранилища нужно захватывать **оба** объекта.

## 📖 Глоссарий

| Термин | Определение |
|---|---|
| **Активность** | Стандартное поле подчинённого регистра. `Истина` — запись участвует в расчётах, `Ложь` — есть в регистре, но ни на что не влияет. |
| **Ведущее измерение** | Измерение регистра, которое индексируется по умолчанию, обнуляет записи при удалении объекта и добавляет команду перехода в форму объекта. |
| **Графа журнала** | Столбец журнала документов. Указывается имя + реквизит документа-источника. |
| **Декартово произведение** | Соединение «каждый с каждым» без условия связи. Количество строк = произведение количеств. |
| **Журнал документов** | Объект конфигурации для отображения списка документов разных видов как одной таблицы. Физически дублирует данные документов. |
| **Запрет незаполненных** | Свойство измерения регистра: не даёт записать запись с пустым значением. |
| **Измерение** | Поле регистра, в разрезе которого ищутся данные (например, `Контрагент`, `Номенклатура`). Входит в ключ. |
| **Ключ регистра** | Набор измерений (+ период, если периодический; + регистратор, если подчинён и периодичность ≥ регистратор). **Номер строки не входит.** |
| **Конструктор движений** | Инструмент конфигуратора для настройки переноса данных из документа в регистр. Генерирует процедуру `ОбработкаПроведения`. |
| **Набор записей** | Аналог таблицы в оперативной памяти. `Движения.ИмяРегистра` — набор записей конкретного регистра. |
| **Независимый регистр** | Режим записи регистра сведений: записи делаются вручную/кодом, без документа-регистратора. |
| **Номер строки** | Стандартное поле подчинённого регистра. Номер записи (не номер строки документа!). **Не входит в ключ** регистра сведений. |
| **NULL** | «Значение не может быть получено». Не 0, не пустая строка, не «неопределено». Появляется в журнале, если для документа нет источника данных. |
| **ОбработкаПроведения** | Процедура модуля объекта документа, вызываемая при проведении. Сюда конструктор движений пишет код переноса данных в регистр. |
| **Обычная группа** | Контейнер на форме без визуального разделения (в отличие от «Страниц» = вкладок). |
| **Период** | Стандартное поле подчинённого регистра. Момент времени, с которого действует запись. |
| **Периодичность** | Свойство регистра сведений: позволяет хранить историю. Даёт «Срез последних» / «Срез первых». |
| **Подчинение регистратору** | Режим записи регистра сведений: записи делает документ. Появляются поля `Период`, `Регистратор`, `НомерСтроки`, `Активность`. |
| **Полное соединение** | Тип соединения: все строки обеих таблиц. NULL возможен с обеих сторон. |
| **Правое соединение** | Тип соединения: все строки правой таблицы + совпадения из левой. NULL — в левой части. |
| **Левое соединение** | Тип соединения: все строки левой таблицы + совпадения из правой. NULL — в правой части. |
| **Внутреннее соединение** | Тип соединения: только совпавшие строки. NULL **не бывает** по определению. |
| **Регистр сведений** | Объект конфигурации для хранения состояния (периодических данных, истории). Поля: ресурсы, измерения, реквизиты. |
| **Регистратор** | Документ, сделавший запись в регистр. Стандартное поле подчинённого регистра. |
| **Ресурс** | Поле регистра, которое хранит данные (например, `Цена`). |
| **Срез последних** | Встроенный функционал периодического регистра: получить последнюю запись на момент времени. |
| **Хранилище конфигурации** | Механизм совместной работы нескольких программистов с одной конфигурацией. Захват объектов, единая структура. |
| **Функциональная опция** | Механизм включения/отключения функциональности. Может автоматически скрывать реквизиты с одним типом данных. |

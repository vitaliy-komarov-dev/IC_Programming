## 🚀 Шпаргалка (1–2 страницы)

### 🎫 Лицензии 1С

| Тип | Пользователей | Ограничения | Стоимость |
|---|---|---|---|
| **Учебная** | 1 одновременно | Лимит данных, нельзя задать пароль | бесплатно (учебный центр) |
| **Девелоперская** | 2 одновременно | Нет лимита записей, «не для коммерции» | бесплатно на сайте 1С |
| **Боевая** | По лицензии | — | платно |

### 🖥️ Клиенты

| Клиент | Для кого | Что ставить |
|---|---|---|
| **Толстый** | Программист | полная установка |
| **Тонкий** | Пользователь | можно вообще ничего (веб) |
| **Конфигуратор** | Разработчик | входит в полную установку |

### ⌨️ Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Ctrl+S` | Сохранить конфигурацию (в оперативке → в конфигурацию) |
| `F7` | Применить к БД |
| `F5` | Сохранить + применить + запустить отладку (старый сеанс **закрывается без вопросов**) |
| `Insert` | Добавить объект текущего уровня |
| `Ctrl+Shift+↑/↓` | Переместить объект вверх/вниз |
| `F9` / `Ctrl+9` | Копировать |
| `F12` | Перейти к объекту в интерфейсе |
| `Shift+Del` | Непосредственное удаление (лучше запретить пользователям) |

### 🧩 Ограничения на имена объектов

- ✅ Разрешено: **буквы (лат./кирилл.), цифры (не в начале), `_`**
- ❌ Запрещено: `+ - = . ,` и любые другие спецсимволы
- 📏 Регистр не важен
- 🐪 Принято: CamelCase (каждое слово с большой буквы)
- 🔤 Полное имя = путь → может совпадать в разных группах

### 🗄️ Справочники: стандартные реквизиты

| Реквизит | Тип | Назначение |
|---|---|---|
| **Ссылка** | `СправочникСсылка.<Имя>` | УИД, неизменяем, появляется при 1-й записи в БД |
| **Код** | строка/число | Уникальный, автонумерация (по умолчанию) |
| **Наименование** | строка (≤150) | Для пользователя |
| **Родитель** | `СправочникСсылка.<Имя>` | Только для иерархических |
| **ЭтоГруппа** | булево | `true` = группа, `false` = элемент |
| **ПометкаУдаления** | булево | Помечен на удаление |
| **Предопределённый** | булево | Создан разработчиком |

### 🎨 Представления объекта (4 поля)

| Поле | Что задаёт | Число |
|---|---|---|
| Представление объекта | Имя команды создания | ед. |
| Расширенное представление объекта | Заголовок формы объекта | ед. |
| Представление списка | Имя команды открытия списка | мн. |
| Расширенное представление списка | Заголовок формы списка | мн. |

> 💡 Если не заполнено — берётся **синоним**. Если заполнено представление, но не расширенное — расширенное = представление.

### 🗂️ Порядок подсистем

- По умолчанию — **алфавитный** (по синониму).
- Меняется: `Конфигурация → Открыть командный интерфейс конфигурации` (или ПКМ по корню).
- Синие стрелочки ↑↓ = порядок важен. Их отсутствие = не важен.

### 🎯 Команды справочника

| Вид справочника | Команд создания |
|---|---|
| Линейный | 1 (элемент) |
| Иерархический | 2 (группа + элемент) |
| Иерархический + предопределённые | 4 (ещё предопр. элемент + предопр. группа) |

### 🔧 Режим совместимости

- Определяет, под какую версию платформы сделана конфигурация.
- «Не использовать» = работаем на последней платформе.
- **Вниз не опускается**, вверх — можно (с проблемами).
- У нас: платформа `8.3.27`, режим `8.3.26`.

## 📚 Полный конспект

### 1. Введение в курс

#### Структура курса (4 официальных курса 1С)

1. **Азы** (АЗО) — основные объекты, запросы, решение оперативных задач
2. **Основные объекты**
3. **Запросы**
4. **Система компоновки данных (СКД)** — формирование отчётов

> 🎓 Курс идёт по официальной программе 1С с сертификацией.

#### Логика обучения

- Первый блок — «мышечный» (работа мышкой, знакомство).
- Второй — углубление в программирование.
- Первые два блока идут **с нуля**, база продолжается со второго (переделываем то, что сделали).

#### Формат

- Онлайн, преподаватель не видит слушателей → сложно с жестами (рисует в Paint).
- Блок-схемы — один из способов описания алгоритмов.
- Методичка по первому блоку выдаётся в бумажном виде (у администратора).

- Смешанное написание (русский + английский) считается дурным тоном.

### 3. Установка и варианты клиентов

| Клиент | Назначение |
|---|---|
| **Толстый клиент** | Полная установка, для программистов |
| **Тонкий клиент** | Работа пользователя (в т.ч. через веб-интерфейс) |
| **Конфигуратор** | Разработка |

#### Установка

- Официальная версия — **архив**, его обязательно **распаковать** перед установкой. Установка «из архива» → некорректная работа.

#### Управляемые формы

С платформы 8.3 вся работа с данными вынесена на сервер. Клиент занимается только отображением — форма полностью готовится на сервере и приходит клиенту готовой. Именно поэтому стало возможно работать через браузер.

### 4. Создание информационной базы

**Путь:** `Конфигуратор → Файл → Новая ИБ`

#### Два варианта подключения

1. **Создание новой ИБ** (наш путь) — пустая или из шаблона
2. **Подключение к существующей** — к файловой базе или к серверу СУБД

#### Файловая vs клиент-серверная

- **Файловая** (по умолчанию) — БД в файле на диске, работу с данными ведёт сама 1С.
- **Клиент-серверная** — нужен поднятый сервер СУБД (PostgreSQL, MS SQL, Oracle, IBM DB2).

#### Параметры создания ИБ

| Параметр | Что задаёт |
|---|---|
| **Имя ИБ** | Локальное имя в списке (у каждого компа своё) |
| **Каталог** | Где физически лежит база. **Не «Мои документы»** — лучше отдельный диск |
| **Язык по умолчанию** | Русский |
| **Основной режим запуска** | Обычно «автоматически» |
| **Версия платформы** | Можно зафиксировать |
| **Разрядность** | 32 или 64 бита |

#### Про разрядность

- 64-битная ОС видит больше памяти (адресов) → меньше «ячеек» → эффективнее.
- Некоторые старые конфигурации (ERP) — только 32 для пользователя, 64 для конфигуратора.
- Пример: одна база может открываться двумя ярлыками — 32-бит и 64-бит.

#### Про диск и кластеры

- Файл занимает минимум 1 **кластер** (например, 4 КБ), даже если сам весит 43 байта.
- Много мелких файлов — зло: место расходуется неэффективно.
- Windows после загрузки живёт в оперативке. Всё, что редактируется в конфигураторе, тоже в оперативке → **Ctrl+S** часто.

### 5. Конфигуратор: базовые понятия

#### Дерево конфигурации

- Корень — «Конфигурация» (владелец всех объектов).
- У каждого объекта — свой набор **свойств** (палитра свойств).
- **Палитра свойств** — динамическая, привязана к текущему объекту.
- **Окно объекта** — живёт независимо от дерева (частая ошибка: смотришь в дерево, а палитра показывает не то).

#### Ограничения на имена

- ✅ Разрешено: **буквы (лат./кирилл.), цифры (не в начале), `_`**.
- ❌ Запрещены: `+ - = . ,` и другие спецсимволы (у каждого — системный смысл в языке).
- Регистр не важен.
- Принято писать каждое слово с большой буквы (CamelCase).

#### Синоним и комментарий

- **Синоним** — имя для пользователя. Если не задан явно — собирается из имени (подчёркивания → пробелы).
- Если синоним задан **вручную** — переименование объекта его уже не меняет.
- **Комментарий** — для программиста, пользователь не видит. Принято хранить дату, автора, задачу.

#### Уникальность имён

- Полное имя = путь, поэтому «Общие / Картинка / Общая» и «Общие / Подсистема / Общая» — разные полные имена.

### 6. Режим совместимости

- Определяет, под какую версию платформы сделана конфигурация.
- «Не использовать» = работаем на последней платформе.
- При обновлении платформы меняется внутренний механизм. Чтобы старое типовое решение работало, нужно протестировать, обновить, и только потом поднимать режим совместимости.
- **Вниз не опускается**, вверх — можно (с проблемами).
- Если база сделана на версии выше — не откроется. Нужно обновить платформу.
- У нас: **8.3.27**, режим совместимости **8.3.26**.

### 7. Подсистемы и командный интерфейс

#### Зачем нужны подсистемы

1. **Сборка интерфейса** — команды пользователя собираются автоматически.
2. **Группировка объектов** — чтобы потом с группой можно было сделать одно действие.

**Уровни:**
- 1-й → панель разделов
- 2-й → подзаголовки
- 3-й и глубже → только сортировка

#### Свойства подсистемы

| Свойство | Значение |
|---|---|
| **Имя** | Внутреннее, для программиста |
| **Синоним** | Для пользователя |
| **Включать в командный интерфейс** | Галочка — команда в панель раздела |
| **Картинка** | Только для подсистем 1-го уровня |

#### Картинки

- Стандартные (встроенные) или свои.
- Формат по умолчанию **64×64** (больше — сожмёт).
- Связь «подсистема ↔ картинка» нужно **подтвердить** кнопкой ОК.
- Если на картинку есть ссылка — удалить нельзя.

#### Порядок подсистем

- По умолчанию — **алфавитный** (по синониму).
- Меняется: `Конфигурация → Открыть командный интерфейс конфигурации` (ПКМ по корню).
- Синие стрелочки ↑↓ = порядок важен. Их отсутствие = не важен.
- Быстро: `Ctrl+Shift+↑/↓`.
- Порядок определяет разработчик конфигурации, не пользователь.

#### Настройка панелей

- `Настройки → Настройки панелей` (или «Сервис и настройки» — старое название).
- Пользователь может перенастроить всё под себя.
- «Вернуть стандартные» = вернуть то, что сделал разработчик в конфигураторе.
- **Настройки панели разделов** → убрать ненужные подсистемы, отключить картинки, расположить текст под картинкой.
- Часть настроек — **на сеанс** (разделение окон), часть — **навсегда** (порядок панелей).

#### Группировка панелей

- Можно объединять панели в **группы** (визуальная иерархия).
- Drag & Drop: на **элемент** → встаёт перед ним; на **группу** → в конец группы.

### 8. Справочники

#### Назначение

Хранить однотипную информацию — набор записей с одинаковым набором свойств.

#### Виды

| Вид | Особенности |
|---|---|
| **Линейный** | Без иерархии, плоский список |
| **Иерархический** | Галочка «Иерархический» → появляются **Родитель** и **ЭтоГруппа** |

#### Иерархия

- **Иерархия групп и элементов** (наш вариант) — родитель только группа, элемент — листочек.
- **Иерархия элементов** — родитель может быть элемент (для подразделений).
- Ограничения на уровни нет (в отличие от субконто в бухгалтерии).
- Обход дерева — через **рекурсию** (зло: непонятно, когда останавливаться + жрёт оперативку).

#### Стандартные реквизиты справочника

| Реквизит | Назначение |
|---|---|
| **Ссылка** | УИД. Появляется при 1-й записи в БД, никогда не меняется. Состоит из номера таблицы + УИД + временной штамп. |
| **Код** | Уникальный (по умолчанию), автонумерация. Строка или число. |
| **Наименование** | То, что видит пользователь, ≤150 символов. |
| **Родитель** | Ссылка на ближайшего родителя (только для иерархических). Тип: `СправочникСсылка.<Имя>`. |
| **ЭтоГруппа** | Булево: `true` — группа, `false` — элемент. |
| **ПометкаУдаления** | Булево. |
| **Предопределённый** | Булево. |

#### Представления объекта

| Поле | Что задаёт | Число |
|---|---|---|
| **Представление объекта** | Имя команды создания | ед. |
| **Расширенное представление объекта** | Имя заголовка формы объекта | ед. |
| **Представление списка** | Имя команды открытия списка | мн. |
| **Расширенное представление списка** | Имя заголовка формы списка | мн. |

**Правило:** если не заполнено — берётся синоним. Если заполнено представление, но не расширенное — расширенное = представление.

#### Предопределённые элементы

- Разработчик может **описать будущую запись** справочника.
- В режиме пользователя помечен **жёлтой точкой**.
- Если случайно попали в код существующего элемента — система предупредит, но даст сохранить.

#### Быстрый выбор и история выбора

- **Быстрый выбор** — выпадающий список (удобно при малом количестве).
- По умолчанию в «Такси» — **история выбора** (то, что уже использовали).
- Можно отключить.

#### Формы и режимы просмотра

- **Форма списка** — заголовок из «Расширенного представления списка».
- **Форма объекта (карточка)** — заголовок из «Расширенного представления объекта».
- **Форма выбора** — по трём точкам, есть кнопка «Выбрать», нет команд «Создать».
- Режимы просмотра: **Иерархический список** / **Список** / **Дерево**.
- При закрытии форма запоминает настройки пользователя.

#### Команды справочника

| Вид | Команд создания |
|---|---|
| Линейный | 1 (элемент) |
| Иерархический | 2 (группа + элемент) |
| Иерархический + предопределённые | 4 (+ предопр. элемент + предопр. группа) |

> 💡 В панели навигации по умолчанию видны только команды **открытия списка**. Команды создания — в панели действий.

#### Флажок «Создавать родителя при создании элемента»

- Позволяет ввести несуществующую группу прямо в поле «Родитель» — система предложит её создать.
- По умолчанию включён.

### 9. Полезные технические отступления

#### Кодировка и сравнение

- Все данные в компьютере — нули и единицы.
- Кодировка — таблица, где каждому символу сопоставлен набор 0/1.
- Порядок в кодировке: цифры → спецсимволы → латиница → остальные языки. Поэтому «А» латинская меньше «А» русской, пробел — ещё раньше.
- В 1С с 8.3.19 в запросах **ведущие пробелы отсекаются**.

#### Булев тип

- Занимает **один бит** по определению, но система выделяет больше → «злой» тип.
- Неявное преобразование: 0 = Ложь, всё остальное = Истина.
- Пример зла: разработчики сделали так, что сеансы при отключении пользователя не закрывались → память на сервере кончилась → разбирались 2 дня.

#### Цикл разработки

| Действие | Что происходит |
|---|---|
| `Ctrl+S` | Сохранить (в конфигурацию). Появляется `<!>` |
| `F7` | Применить к БД |
